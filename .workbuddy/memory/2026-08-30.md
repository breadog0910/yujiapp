- 问题：手机浏览器端（非 PWA）原本把房间铺满任意比例视口 + `object-fit:cover` 裁切背景，导致家具百分比坐标相对比例不同的容器而错位。
- 改法：`yuji-app/css/main.css` 新增 `@media (max-width:767px) and (display-mode: browser)` 块（仅手机浏览器）：
  - `.app-main` 改纵向滚动容器；

- 关键前提：家具层 `--care-h:14.69%` 与气泡条高度同比例，家具只在底部 14.69% 之上分布 → 气泡条永不遮挡家具，任意滚动位置无重叠。

## 修订：首版仍滑不动 → 找到真正根因（flex min-height:auto）
- 首版用 `@media (max-width:767px) and (display-mode:browser)`：用户实测仍无法滚动。两个叠加问题：
  1) `display-mode:browser` 媒体特性不被识别时整条 @media 被丢弃 → 规则不生效；
  2) **更关键的结构 bug**：`.app-container` 是 flex column，`.app-main` 为 `flex:1`，flex 子项默认 `min-height:auto` 不会收缩到比内容矮 → 房间(844px)把 `.app-main` 撑高、溢出 `.app-container(overflow:hidden)` 被裁掉，内部 `overflow-y:auto` 永不触发 → 根本不滚动。桌面手机壳因房间恰好贴合、不触发滚动，所以此前没暴露。
- 修订方案（main.css）：
  - 可滑动规则改为不依赖 display-mode：`@media (max-width:767px)` 默认即等比滚动舞台；
  - 新增 `@media (max-width:767px) and (display-mode:standalone)` 把规则撤销、恢复原铺满全屏 → 手机端 PWA 逻辑保持未变；
  - **关键修复**：`.app-main` 加 `min-height:0`，解除 flex 收缩约束，使其按分配高度内部滚动。
- 验证方式：手机浏览器开 index.html，房间超视口时主内容区应能纵向滑动；家具百分比与背景 1:1 不变。沙箱内无法跑移动视口真机/浏览器，故以代码分析验证。
- 状态：已提交并推送（见 git log）。

## 二次修订：前两次「手机浏览器可滑动」仍不生效 → 真正根因是 CSS 层叠覆盖（cascade）
- 现象：用户两次反馈「还是滑动不了」。代码逻辑（媒体查询内容）本身是对的，但**规则根本没被应用**——被同特异性、源码更晚出现的基础规则覆盖了：
  1) `main.css` 内：媒体查询 `.app-main{overflow-y:auto}`（约 184 行）被**同文件更晚**的 `.app-main{overflow:hidden}`（约 258 行）覆盖 → `.app-main` 永远是 hidden，不滚；
  2) 跨文件：`main.css` 媒体查询 `.tab1-room{position:relative;aspect-ratio:390/844}` 被 **tab1-home.css（加载更晚）** 同名 `.tab1-room{position:absolute;inset:0}` 覆盖 → 房间恒为 absolute 铺满、不会变高成 844px，于是没有可滚内容。
- 修法（main.css，治本）：把媒体查询选择器**提高特异性**，压过更晚的基础规则：
  - `.app-main` → `.app-container > .app-main`（特异性 1,1,0），确保 `overflow-y:auto + min-height:0` 生效；
  - `.tab1-room` / `.tab1-bg` / `.tab1-care` → 加 `#tab1 ` 前缀（`#tab1 .tab1-room` 1,1,0），压过 tab1-home.css 同名规则；
  - PWA standalone 撤销块同步用同等特异性、且源码更靠后 → 在 standalone 模式仍胜出、保持原铺满不变。
- **真机验证（Playwright + 系统 Chrome，390×844 移动视口）确认生效**：
  - `.app-main`: `overflowY=auto`、`minHeight=0px`、`clientH=780 / scrollH=844`；
  - `.tab1-room`: `position=relative`、`height=844px`、`aspectRatio=390/844`；
  - 滚动实测 `scrollTop` 设 300 实际到 64（=844−780 最大滚量）→ **滚动功能可用**。
- 附加：`index.html` 把 `main.css`/`tab1-home.css` 缓存号 `?v=80→?v=81`，防止浏览器缓存旧的坏 CSS（用户需硬刷新）。
- 经验：**跨文件/同特异性覆盖是 CSS 常见坑**，改完务必用真实渲染（Playwright 移动视口测 computed style + scrollTop）而非纯推理验证。
- 状态：已提交并推送（见 git log）。
