## Git 推送踩坑：系统代理 127.0.0.1:7892 失效
- 现象：`git push` 报 `Failed to connect to github.com:443 over proxy 127.0.0.1 ... Could not connect to server`。
- 原因：git 全局配了 `http.proxy/https.proxy=http://127.0.0.1:7892`（系统代理/Clash 类），但代理软件未运行 → 连不上。
- 解决（可复用）：**清空代理后直连推送**即可成功：
  `http_proxy= https_proxy= HTTP_PROXY= HTTPS_PROXY= git -c http.proxy= -c https.proxy= push origin main`
  同理 `ls-remote` 核对也要清代理（否则仍走失效代理报错）。
- ⚠️ 后续（12:54）：两种方式**都失败**——直连 `Failed to connect ... after 21s`（超时被拦）、代理 `over proxy 127.0.0.1`（无监听）。诊断：
  - `netstat -ano | grep LISTENING | grep -E ":(7890|7891|7892|1080|10809|8888)"` → 无任何代理端口监听 = 代理软件未运行。
  - `nslookup github.com` → 能解析（20.205.243.166），DNS 正常，是 TCP 443 出不去。
  - 结论：**必须先由用户启动代理软件（Clash 等，监听 127.0.0.1:7892）才能推送**；git 全局已配好该代理，启动后直接 `git push origin main` 即可。提交本身在本地不会丢。
- ✅ 13:03 代理恢复（127.0.0.1:7892 重新监听）后推送成功：`eb0f35a..499a26f main -> main`，远程核对 = 499a26f。**排查顺序可复用：先看代理端口是否 LISTENING → 端口在就直接 push；端口不在则直连（清代理）；两种都不通就是网络/代理软件问题，需用户手动启动代理。**
